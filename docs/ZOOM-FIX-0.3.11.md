# 0.3.11 확대·축소 개선

기준일: 2026-11-10. 이전 0.3.10 보관본은 유지합니다.

## 원인과 변경

기존 배율 목록은 더보기 안에 있었고 편집 캔버스만 바꿨습니다. PDF의 pt를 WPF의 DIP와 같은 값으로 표시해 native 100%와 편집 100% 기준도 달랐습니다.

- 리본에 작은 `− / 배율 / + / 맞춤 / 쪽` 컨트롤을 추가했습니다. 한 줄 배치를 유지합니다.
- native 보기에서는 이 앱 자체 창의 PDF 확대·축소·맞춤 컨트롤을 사용하므로 줌마다 파일을 다시 열지 않습니다. 현재 페이지를 유지합니다. 다른 앱을 조작하거나 조회하지 않습니다.
- 100%=PDF pt의 96/72배 DIP로 통일했습니다. 보기 → 편집 → 보기의 종이 표시 크기를 맞춥니다.
- 편집/스프레드의 Ctrl+휠과 Ctrl++/−/0을 연결했습니다. native PDF의 자체 Ctrl+휠도 유지합니다. native Ctrl 조작 중과 직후 배율 표시를 갱신하며, idle에는 접근성 트리를 반복 조회하지 않습니다.
- 편집 확대 시 포인터 또는 화면 중심을 기준으로 스크롤 오프셋을 보정합니다. 문서·주석 좌표는 변경하지 않습니다.
- 작은 도면 맞춤을 위해 5%까지, 큰 확대는 800%까지 지원합니다. native 프리셋은 지원되는 가까운 단계로 적용하고 실제 배율을 표시합니다.
- 큰 배율 편집은 입력 중이 아니면 최대 3600px 배경으로 지연 갱신합니다. 이미지 캐시 약 96MB 예산, 줌 도중 조절점의 화면 크기 유지, 다중 페이지 가로 스크롤을 반영했습니다.

## 코드 연결

- `PdfEditorView.Zoom.cs`: 공통 배율, 위치 보정, 맞춤, 키/휠, 지연 해상도 갱신과 native 표시 동기화.
- `MainWindow.ViewPosition.cs`: 자신이 소유한 WebView2의 native 컨트롤 호출과 페이지 폭 읽기.
- `PdfEditorView.Unified.cs` / `MainWindow.PdfEdit.cs`: 보기·편집 전환 배율 연결.
- `PdfEditorView.Pages.cs`: 2/3페이지 배율·행 너비·가로 스크롤.
- `PdfEditorView.xaml`: 리본과 편집 ScrollViewer의 배선.
- `pdf_edit.py` / `PdfEditService.cs`: 선택적 고해상도 렌더의 상한.
- `ZoomUiTest.cs`, `Test-EditorAudit.ps1`: native 확대/맞춤 시 무재로딩·페이지 유지, 전환 배율·앵커·조절점·고해상도·스프레드·원본/주석 보존.

## 검증

`pwsh -NoProfile -File scripts/Test-EditorAudit.ps1 -IncludeUi`로 기존 편집/선택/메모/저장 검사와 새 줌 검사를 실행합니다. 0.3.11은 16단계이며 결과는 `artifacts/audit-0.3.11/`에 보관합니다. native 컨트롤이 준비되는 시간은 navigation 완료와 다를 수 있어 실제 페이지 준비를 기다려 검사합니다.

본문 편집·2/3페이지 이미지 보기의 기존 제한은 유지합니다. 현행 설치 ZIP 0.3.10과 이 수정 소스를 구분하며, 새 설치판은 별도 제작해야 합니다.
